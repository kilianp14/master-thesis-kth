\section{Adaptive Fast Mode Switching}
\begin{itemize}
    \item Choice of operating Mode (Regular Paxos, Fast Paxos) is made dynamically whenever a node wants to append something to the replicated log
    \item Important: This decision is made INDEPENDENTLY for each node, meaning that different servers can have varying operating modes
    \item Leader of a ballot always operates in normal mode since this will always be faster/ more successful, as a majority quorum is easier to achieve than a fast quorum and there is no forwarding penalty which would make it slower for a follower
\end{itemize}

\subsection{Mode Interoperability}
\begin{itemize}
    \item Different Accept Status in accept/accepted messages: FastAccept, LeaderAccept, SlowAccept
    \item Operating Mode during Append: Fast Paxos -> Broadcast Accept with status FastAccept
    \item Regular Paxos -> Forward Append Request to Leader who then broadcasts with LeaderAccept
    \item Leader keeps a record of accepted messages for all open slots and if leader detects a collision: Broadcasts Slow Accept for that slot with the determined value
    \item Followers react to the status in the accept phase messages with their accept logic: FastAccept and LeaderAccept must not override slots with an accepted value, while SlowAccept should always override
\end{itemize}
