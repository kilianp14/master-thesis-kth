\section{\glsfmtfull{SMR}}
A common way of providing fault tolerance for a service and thereby improving its availability is to operate multiple servers that each hold the same state. These replicas can either be used to shadow a main node that answers requests and take over in case it fails, or they can be, potentially globally, distributed to all serve requests of local clients.

To ensure that the state of replicas does not diverge, one approach is to decide on the execution of the same sequence of deterministic operations across all nodes. This is referred to as \gls{SMR} \cite{Schneider-ReplicatedStateMachines-1990}. The Raft protocol \cite{Ongaro-Raft-2014} popularized the concept of a replicated log as the central abstraction for developers of such services. It is specifically designed around managing a linear, append-only log, which stores the operations necessary for \gls{SMR}. Since the log always contains the same deterministic operations across all replicas, executing them in order will always result in nodes having the same state at the end.

The underlying problem of the replicated log abstraction, which Raft and other similar protocols solve, is defined as uniform sequence consensus and is described in Section \ref{sect:uniform_sequence_consensus}. Figure \ref{fig:state_machine_replication} displays the described common way of designing a fault-tolerant system using a replicated log.

\subsection{Uniform Sequence Consensus}
\label{sect:uniform_sequence_consensus}
As described, the problem of agreeing on a value between coordinating processes lies at the core of fault-tolerant distributed systems. Any distributed algorithm that relies on different nodes having a common state or performing the same action requires solving the consensus problem in some way.

We can formalize the abstraction layer of \textit{uniform consensus} according to Cachin et al. \cite{Cachin-ReliableDistributedProgramming-2011}. A process can send a proposal with a value to the consensus layer, and it outputs an event with the final decided value. An algorithm for uniform consensus must satisfy the following properties:
\begin{itemize}
  \item[] \textit{Termination:} Every correct process eventually decides some value.
  \item[] \textit{Validity:} Every decided value was previously proposed.
  \item[] \textit{Integrity:} No process decides more than once.
  \item[] \textit{Uniform agreement:} No two processes decide different values.
\end{itemize}

Since uniform consensus is impossible to achieve in an \textit{asynchronous system} with no bounds on clock drift, transmission delay, and processing time \cite{Fischer-ConsensusAsynchronousSystem-1985}, we consider networks like the Internet as \textit{partially synchronous systems} throughout this thesis. This means that there will always be phases where such bounds exist, which are long enough that algorithms can make progress.

\subsection{Conformal Prediction}
For a general input $X$ and output $y$ and a calibration set $\{(X_1, y_1), ..., (X_n, y_n)\}$ of size $n$ containing labeled unseen data, the following steps should be completed:

\begin{enumerate}
    \item Define the score function $s(x, y) ∈ \mathbb{R}$ (larger scores encode worse agreement between $x$ and $y$)
    \item Compute $\hat{q}$ as the $\frac{\lceil(n+1)(1−\alpha)\rceil}{n}$ quantile of the calibration scores $s_1 = s(X_1 , Y_1), ..., s_n = s(X_n , Y_n)$
    \item Use this quantile to form the prediction sets for new example $X_{test}$: $\mathcal{C}(X_{test}) = \{y: s(X_{test}, y) \le \hat{q}\}$
\end{enumerate}

Using this method, we can guarantee that the probability of the true value $Y_{test}$ being in the prediction set is not less than $1 - \alpha$ under the assumption that the test point stems from the same distribution as the points in the calibration set: $\mathbb{P}\left(Y_{test} \in \mathcal{C}(X_{test})\right) \ge 1 - \alpha$

The usefulness of the prediction sets is primarily determined by the score function.
